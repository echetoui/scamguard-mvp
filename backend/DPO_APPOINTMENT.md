## 2. DPO RESPONSIBILITIES & AUTHORITY

### 2.1 Core Responsibilities

The Data Protection Officer shall:

#### A. Monitoring & Compliance
- [ ] Monitor compliance with Loi 25 and all applicable data protection laws
- [ ] Conduct regular audits of data processing activities
- [ ] Maintain up-to-date documentation of personal data processing
- [ ] Perform data protection impact assessments (PIA)
- [ ] Track data retention and deletion compliance

#### B. Privacy by Design
- [ ] Review new features/products for privacy implications
- [ ] Recommend privacy-protective measures
- [ ] Consult on data processing lawfulness
- [ ] Advise on data minimization practices
- [ ] Review vendor/processor contracts for data protection clauses

#### C. User Rights Management
- [ ] Handle subject access requests (within 30 days)
- [ ] Manage data deletion requests
- [ ] Process data portability requests
- [ ] Handle complaints and escalations
- [ ] Maintain right-of-access audit logs

#### D. Incident Management
- [ ] Lead data breach incident response
- [ ] Coordinate breach notification (within 72 hours if required)
- [ ] Document incidents in breach register
- [ ] Coordinate with authorities if required
- [ ] Perform post-incident analysis

#### E. Staff Training & Awareness
- [ ] Conduct data protection training for staff
- [ ] Maintain training records
- [ ] Provide guidance on data protection policies
- [ ] Foster data protection culture

#### F. Authority Communication
- [ ] Serve as point of contact for regulatory authorities
- [ ] Respond to inquiries from Loi 25 regulator (CNPQ)
- [ ] Maintain relationships with privacy authorities
- [ ] Report on DPO activities quarterly

### 2.2 Authority & Independence

The DPO is granted the following authority:

✅ **Access Authority**
- Full access to all systems containing personal data
- Access to relevant documentation and records
- Right to interview staff on data processing

✅ **Decision Authority**
- Authority to recommend data processing changes
- Authority to halt non-compliant processing
- Authority to prioritize privacy concerns

✅ **Resource Authority**
- Dedicated budget for DPO operations
- Authority to hire/contract support staff
- Authority to procure privacy tools/services

✅ **Reporting Authority**
- Direct report to Executive Leadership
- Annual report to Board (if applicable)
- Quarterly reports to Compliance Committee

✅ **Independence**
- **Protection from Retaliation:** DPO cannot be dismissed or penalized for performing duties
- **No Conflicts:** DPO role cannot have conflicting data controller responsibilities
- **Confidentiality:** DPO communications are confidential (privileged)

## 5. KEY RESPONSIBILITIES - DETAILED

### 5.1 Subject Access Requests (SAR)

**Process:**
1. User submits request to privacy@scamguard.ca
2. DPO verifies identity (security question or email confirmation)
3. DPO compiles personal data from all systems
4. DPO removes third-party data (data not directly about user)
5. DPO formats as readable file (CSV, JSON, PDF)
6. DPO sends to user within 30 days
7. DPO logs request and response

**Timeline:** 30 days from receipt (can extend 60 days for complex requests)

**Data Included:**
- ✅ User ID (hashed)
- ✅ Analysis history (text input, results)
- ✅ Consent records (acceptance date/time)
- ✅ Risk scores (per analysis)
- ✅ Activity logs (date/time stamps)
- ❌ Excluded: Third-party data (alerts from CAFC/SQ)

### 5.2 Data Deletion (Right to be Forgotten)

**Process:**
1. User requests deletion (via privacy@scamguard.ca)
2. DPO verifies request legitimacy
3. DPO checks for legal holds (compliance, litigation)
4. DPO initiates deletion workflow
5. DPO permanently deletes:
   - User hashed ID
   - Analysis history
   - Consent records
   - Activity logs
6. DPO confirms deletion to user
7. DPO logs deletion for audit trail

**Timeline:** 30 days

**Exceptions:**
- ❌ Cannot delete: Alerts (CAFC/SQ data, not about user)
- ✅ Can delete: User-specific analysis records

### 5.3 Data Breach Management

**Response Timeline:**
1. **Immediate (0-1 hour):** Detect & contain breach
2. **4 hours:** DPO notified, incident logged
3. **24 hours:** Impact assessment completed
4. **48 hours:** Decision on user notification
5. **72 hours:** User notification sent (if required by law)
6. **7 days:** Regulator notification (if required)

**Notification Template:**

```
Subject: Important: Data Protection Notice - ScamGuard Security Incident

Dear [User],

We are writing to inform you of a security incident that may affect your
personal information held by ScamGuard.

Incident Details:
- Date discovered: [DATE]
- Types of data affected: [LIST]
- Individuals affected: [NUMBER]
- Cause: [BRIEF DESCRIPTION]

Actions Taken:
- Incident contained and investigated
- Security measures enhanced
- [ADDITIONAL ACTIONS]

Your Rights:
- Request data access: privacy@scamguard.ca
- Request data deletion: privacy@scamguard.ca
- File complaint: [REGULATORY AUTHORITY]

For questions: privacy@scamguard.ca or call [PHONE]

Sincerely,
ScamGuard DPO Team
```

### 5.4 Data Protection Impact Assessment (DPIA)

**When Required:**
- New feature collecting personal data
- Change to data processing
- System upgrade affecting privacy
- Third-party processor integration

**DPO Assessment:**
1. Identify data types and volumes
2. Assess processing risks
3. Evaluate security measures
4. Document risk mitigation
5. Recommend changes
6. Approve or reject feature

**Timeline:** 2-4 weeks depending on complexity
